# Runbook: troubleshooting

**Триггеры от оунера**:
- «start.sh падает»
- «gitleaks ругается»
- «приложение не запускается локально»

**Предусловие:** оунер сообщил конкретный симптом.

**Постусловие:** причина диагностирована, либо устранена локально, либо передана на эскалацию.

**Читатель — агент.** Причины и коды ошибок здесь — для твоей диагностики, не для пересказа. Оунеру объясняй причину и нужное действие простым языком: переводи жаргон (`pre-commit hook`, `working tree`, `staging`, `revert`, `version floor` и т.п.) в бытовые формулировки и не вставляй сырые коды ошибок без расшифровки. Шаги ниже в императиве («запушь», «проверь») делаешь ты сам; шаги с пометкой «оунер сам» / «pre-agent» — это действия оунера (ввод логина, установка утилит), ты их только подсказываешь.

---

## Секция 1: start.sh

> Все ошибки ниже означают, что какой-то prerequisite не был установлен до клонирования template'а. Полный список — [runbook:onboarding](./onboarding.md). Если симптом не совпадает ни с одним кейсом ниже — запусти `./infra/start.sh` под `bash -x`, чтобы видеть какой шаг падает, и сообщи вывод.

### Симптом: `gh: command not found` / `gh-not-installed`

`start.sh` не находит GitHub CLI.

Действие: запусти `make setup` — на macOS он поставит `gh` (и остальные утилиты) через Homebrew. На другой ОС `make setup` подскажет команду для ручной установки (`brew install gh` / `sudo apt install gh` / https://cli.github.com/manual/installation). Затем запусти `./infra/start.sh` заново.

---

### Симптом: `gh-not-authed` — GitHub CLI не авторизован

GitHub CLI установлен, но не авторизован в аккаунте оунера.

Действие: оунер сам выполняет (pre-agent шаг):
```bash
gh auth login
# Выбери: GitHub.com → HTTPS → Login with web browser
```
После успешного входа запустить `./infra/start.sh` заново.

---

### Симптом: `start.sh` пишет «gh CLI не авторизован», хотя ты авторизован

Скорее всего агент (Codex) запущен в песочнице без доступа к сети (`workspace-write`, по умолчанию сеть выключена). Сетевые операции (проверка GitHub, `git push`, `gh pr`) при этом падают. Включи в Codex режим **Full Access** (команда `/approvals` → Full Access, либо селектор режима рядом с полем ввода) и повтори. На Claude Code сеть в Bash доступна по умолчанию — симптом специфичен для Codex.

---

### Симптом: `gitleaks: command not found` / `precommit-not-installed`

Не установлен `gitleaks` — инструмент проверки секретов, необходимый для pre-commit hook.

Действие: запусти `make setup` — на macOS поставит `gitleaks` через Homebrew. На другой ОС — вручную (`brew install gitleaks` / бинарь с https://github.com/gitleaks/gitleaks/releases). Затем запусти `./infra/start.sh` заново.

---

### Симптом: я на Windows, `start.sh` отказывается работать

`start.sh` и git-хуки (gitleaks) работают только в POSIX-среде. На Windows весь
workflow живёт внутри **WSL2 (Ubuntu)** — там окружение = Linux.

Рекомендованный путь на Windows — **Codex** (Claude Code на Windows в WSL пока не
работает напрямую):
1. Установи WSL2: PowerShell от администратора → `wsl --install` → перезагрузка → создай пользователя Ubuntu.
2. Открой терминал Ubuntu и выполни bootstrap (создаёт `~/code/`, ставит `gh`/`gitleaks`/`jq`/`envsubst`, авторизует `gh`):
   `curl -fsSL https://raw.githubusercontent.com/flowwow-sandbox/vibecoder-local/main/infra/bootstrap-wsl.sh | bash`
3. В Codex Desktop переключи агента в WSL-режим (Settings → WSL → перезапуск) и открой проект из `~/code/` (`\\wsl$\Ubuntu\home\<user>\code\...`).

После этого запускай `start.sh` внутри WSL.

Если это другая ОС — эскалация в канал «Песочница».

---

### Симптом: `Имя репо не совпадает со slug` / `invalid-slug`

`start.sh` проверяет соответствие имени GitHub-репозитория и `SANDBOX_SLUG` из `.env`.

Действие:
```bash
# Вариант 1: переименовать репо (быстрее)
gh repo rename <correct-slug>

# После исправления:
./infra/start.sh
```

---

### Симптом: `start.sh` отваливается на первом шаге

`gh` авторизован, но репо ещё не запушен в GitHub.

Действие: запушь ветку `main` в origin, затем повтори `./infra/start.sh`.

## Секция 2: Локальный запуск приложения

> Docker в этом варианте не используется — приложение запускается как обычный процесс (его поднимаешь ты под стек оунера: `make preview` для статичной заглушки, `bun dev` / `uvicorn` и т.п. для реального приложения).

«Не поднимается» — обычная отладка стека, делай как умеешь (читай ошибку процесса, проверь зависимости и занятый порт). Специфика шаблона, про которую не забудь:

- App-код живёт в `app/` — команды стека запускай оттуда (`cd app && bun install`, `cd app && uv sync`), не из корня.
- Статичная заглушка из онбординга поднимается через `make preview` (рендерит `app/index.html.tpl` с подстановкой `SANDBOX_SLUG`), не прямым открытием файла.
- Рантаймы allowlist имеют version floors (Node ≥ 20, Python ≥ 3.11, Bun ≥ 1) — частая причина «у меня не стартует» на новом/чужом ноуте. Сверь версию (`node -v` / `python --version`) с `docs/contracts/safety-rules.md` §1.

Если падает не приложение, а `start.sh` или окружение — это Секция 1.

## Секция 3: Git / gitleaks

### Симптом: gitleaks обнаружил секрет в pre-commit hook

gitleaks заблокировал коммит — нашёл строку, похожую на секрет (API-ключ, токен, пароль).

Действие:
1. Прочитать вывод gitleaks: какой файл, какая строка.
2. Если это реальный секрет — убрать его из файла, добавить в `.gitignore` если нужно.
3. Если это false positive (например, тестовые данные в форме ключа) — добавить исключение в `.gitleaks.toml` (проконсультироваться с owner'ом).
4. **НЕ обходить через `--no-verify`** — это нарушает инвариант безопасности (см. [contracts:safety-rules](../contracts/safety-rules.md)).

---

### Симптом: оунер случайно закоммитил `.env`

**Если push ещё не сделан:** откати коммит, оставь все правки в working tree, убери `.env` из staging.

**Если уже push'нул:** `.env` в истории main — секреты скомпрометированы.
1. Ротировать runtime app-секреты у провайдеров (новый OpenAI key, Telegram-bot token и т.д.).
2. **НЕ просить** «стереть через `git filter-branch` / force-push» — force-push блокирован, скомпрометированный секрет всё равно в кеше GitHub.

После ротации: обновить `.env` через редактор (не в чат). Полный recovery: [runbook:recovery](./recovery.md).

---

### Симптом: как откатить последний коммит, оставив код в working tree

- Если коммит не запушен: откати его локально, изменения в коде оставь (оунер хочет переделать).
- Если уже запушен: откати его revert-коммитом и запушь.

---

### Симптом: squash старых коммитов / `git rebase -i`

**Не делать.** На приватном репо с линейной историей это бессмысленно (история не публичная), и риск превышает выгоду. Force-push блокирован политикой. Если очень нужно — эскалация в канал «Песочница».

---

## Секция 4: Git / откат

### Симптом: как откатиться к старой версии приложения

Откати последний коммит revert'ом через PR-flow: создай ветку `revert/<feature-branch>`, сделай `git revert`, запушь, открой PR, слей.

---

## Когда не получается локально

Эскалация: написать в **канал «Песочница»** с:
- (а) скриншотом ошибки,
- (б) ссылкой на репо,
- (в) slug.
