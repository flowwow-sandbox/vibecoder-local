# Runbook: onboarding

**Триггеры от оунера** (фразы, активирующие этот runbook):
- «запусти онбординг»
- «настрой с нуля»

Также — если ты впервые открылся в репо, видишь что `.env` ещё нет, можешь сам предложить оунеру онбординг.

**Предусловие:** свежеклонированный template-репо; в корне есть `.env.example`, но нет `.env`; оунер уже поставил агент-тул на ноут (Claude Code или Codex — поддерживаемые тулы; Codex — CLI ≥ 0.123.0, нужен для хуков) и плагин методологии `superpowers`. В Claude Code `superpowers` прописан в `.claude/settings.json` → тул предложит поставить его сам при первом открытии репо; в Codex это ручной шаг.

> **Если ведёшь онбординг через Codex:** подходят режимы **«Запрашивать разрешение»** и **«Подтверждать за меня»**; Full Access не требуется. Если `./infra/start.sh` упирается в ограничения, запроси минимально необходимый доступ для исходной команды запуска скрипта целиком: сеть для проверки GitHub и записи для шагов ниже. После разрешения повтори именно этот запуск с теми же аргументами и проверь результат. Дочерние команды наследуют sandbox этого запуска; разрешение на отдельно запущенный `gh` не разрешает следующий запуск скрипта.
>
> В режиме «Подтверждать за меня» запрос проверяет автоматический reviewer, sandbox остаётся активным. Если reviewer отклонил действие, объясни оунеру, что было отклонено и почему; предложи более безопасный вариант или запроси его явное решение. Не повторяй отклонённое действие другим способом без такого решения. [Режимы подтверждения](https://learn.chatgpt.com/docs/sandboxing), [автоматическая проверка](https://learn.chatgpt.com/docs/sandboxing/auto-review).
>
> `workspace-write` сам по себе не гарантирует запрет чтения всех файлов вне проекта: доступ на чтение зависит от [профиля разрешений](https://learn.chatgpt.com/docs/permissions#file-access-limited-to-workspace). Настройки Codex и ограничения sandbox сохраняются.

**Постусловие:** pre-commit hook на gitleaks активен, прототип запускается локально (стартовую заглушку показываешь через `make preview`; реальное приложение поднимаешь сам под его стек).

## Шаги

1. **Поставь утилиты.** Запусти:
   ```bash
   make setup
   ```
   Таргет проверит и доустановит то, чего не хватает (`gh`, `gitleaks`, `jq`, `gettext`). На macOS — автоматически через Homebrew (если Homebrew нет, скрипт даст ссылку на установку). На другой ОС `make setup` подскажет, что поставить вручную.

   Установка через Homebrew или системный пакетный менеджер может потребовать записи вне проекта. Запроси отдельное разрешение на конкретную установку; оунер также может выполнить её сам в обычном терминале. После установки повтори проверку зависимостей.

   > Авторизацию в GitHub оунер обычно уже прошёл раньше. Если `start.sh` ниже сообщит о сбое `gh api user`, сначала проверь сеть и запроси доступ на исходный запуск `./infra/start.sh` целиком в Codex; после разрешения повтори ту же команду с теми же аргументами. Отдельный `gh api user --silent` — только диагностика, разрешение на неё не переносится на запуск скрипта. Если токен отсутствует или проверка сообщает о проблеме авторизации — попроси оунера выполнить `gh auth login` (браузерный код, за него это сделать нельзя).

2. **Проверь окружение и подготовь `.env`.** Запусти `./infra/start.sh` — он проверит окружение (ОС, утилиты). Если `.env` ещё нет, скрипт попросит переименовать.

   Relay инструкцию оунеру — путь зависит от того, где он переименовывает файл (имя начинается с точки, поэтому по умолчанию прячется):
   - **В файловом дереве редактора** (VS Code и т.п.; на Windows вся работа идёт внутри WSL — это типичный путь там): dot-файлы видны сразу — переименуй `.env.example` в `.env` прямо там.
   - **В macOS Finder**: dot-файлы по умолчанию скрыты — сначала нажми `Cmd+Shift+.` (точка), появится сероватый `.env.example`, потом правый клик → Переименовать → `.env` (если macOS переспросит про имя с точкой — подтверди).
   - **В терминале** (если редактора под рукой нет): оунер сам выполняет `mv .env.example .env` (ты — нет, см. ниже).

   После переименования пусть скажет «готово».

   **НЕ делай `mv .env.example .env` сам через Bash** — это обучающий шаг, оунер должен запомнить, где живут его секреты.
   Расскажи оунеру, что это его основной файл, в котором он должен хранить секретные ключи проекта.

   Когда оунер скажет «готово» — запусти `./infra/start.sh` ещё раз. На этот раз setup_env пройдёт ветку «`.env` уже есть» (chmod 600 + audit), ставит `.git/hooks/pre-commit` с gitleaks-проверкой. Если падает — разбери симптом по [troubleshooting](./troubleshooting.md) и повтори.

3. **Покажи, что прототип работает локально.** `./infra/start.sh` готовит окружение, но **само приложение не запускает** — это делаешь ты под конкретный стек (Docker не нужен). Для стартовой заглушки (`app/index.html.tpl`) проще всего:
   ```bash
   make preview
   ```
   Откроется страничка в браузере. Когда у оунера появится реальное приложение (Node, Python, …) — запускай его так, как принято для стека (`bun dev`, `uvicorn`, и т.п.), и дай оунеру локальный адрес.

4. **Готово.** Скажи оунеру: «Онбординг закончен. Теперь дай мне задачу — например "сделай страничку с приветствием и кнопкой".» Дальше работа по [`dev-workflow.md`](../contracts/dev-workflow.md).

## Когда что-то пошло не так

- **Не хватает утилиты (`gh` / `gitleaks` / `jq` / `envsubst` не найдены)** — запусти `make setup` (на macOS поставит через Homebrew). На другой ОС `make setup` подскажет команды для ручной установки.

- **`start.sh` падает с `gh auth`-ошибкой** — различи отсутствие токена и сбой проверки `gh api user`. При проблеме сети проверь подключение и запроси сетевой доступ для исходного запуска `./infra/start.sh` целиком в Codex, затем повтори ту же команду с теми же аргументами. Отдельная диагностика `gh api user --silent` не разрешает запуск скрипта. Если токена нет или диагностика указывает на проблему авторизации — оунер сам выполняет `gh auth login` в терминале и сообщает «готово».

- **Агент не вызывает `brainstorming` / `requesting-code-review` / `systematic-debugging` (скилы `superpowers` недоступны)** — плагин методологии не установлен. Сам поставить не могу (это slash-команда тула), relay оунеру под его тул:
- **Claude Code:** выбери «Code» → «Customize» → «Personal plugins» → «Add plugin» → «Browse plugins», найди superpowers и нажми Установить.
- **Codex:** `/plugins` → найди «superpowers» → Install.

- **Claude ведёт себя странно (читает не те файлы / коммитит без тестов)** — проверь, что hooks на месте:
  ```bash
  ls -la .claude/hooks/
  ```
  Должно быть 8 `.py` файлов: `api-key-leak-detector`, `command-injection-guard`, `destructive-command-guard`, `git-destructive-guard`, `git-no-verify-guard`, `secret-leak-guard`, `working-directory-guard`, `safety_common`. Если папки нет или пуста — переклонируй template.
