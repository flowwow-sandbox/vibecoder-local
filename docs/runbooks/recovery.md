# Runbook: recovery

**Триггеры от оунера**:
- «я сменил ноутбук»
- «переустановил систему»

**Предусловие:** оунер на чистой машине без локального клона репо ИЛИ потерял доступ к существующему репо.

**Постусловие:** локальный клон существует, `.env` восстановлен из парольного менеджера, оунер может продолжать работу.

**Выбор сценария:** Сценарий A — если оунер пишет «сменил ноутбук» и старый ещё есть (можно прочитать `.env`). Сценарий B — если старый ноут недоступен (нужно перевыпустить app-секреты у провайдеров). Сценарий C — это не recovery, это handoff проекта другому пилотнику; делегируй ответственному за платформу.

---

## Сценарий A: старый ноутбук доступен, делается параллельный клон

Старый ноут ещё работает — можно прочитать `.env`.

1. **На старом ноутбуке:** убедись, что нет несинхронизированных коммитов. Скажи агенту «проверь, всё ли запушено, и если нет — запушь». Агент сделает `git status` и `git push` при необходимости.

2. **На новом ноутбуке:** оунер должен сам пройти первоначальную настройку по чеклисту https://sandbox.flowwow.co/start

3. **Клонируй репо.**
   ```bash
   gh repo clone <github_login>/<slug>
   cd <slug>
   ```

4. **Запусти инициализацию.**
   ```bash
   ./infra/start.sh
   ```
   Скрипт попросит переименовать `.env.example` → `.env`. Сделай это в IDE (правый клик → Rename) или через терминал: `mv .env.example .env`.

5. **Восстанови `.env` из парольного менеджера.**
   - Открой `.env` в редакторе IDE.
   - В парольном менеджере найди запись с секретами проекта.
   - Скопируй необходимые значения в `.env`.
   - **Не вставляй значения секретов в чат** — только через редактор напрямую в файл (инвариант №8).

6. **Запусти `./infra/start.sh` ещё раз** — завершит инициализацию (chmod 600, pre-commit hook).

7. **Готово.** Открой тул в папке проекта, продолжай работу.

---

## Сценарий B: старый ноутбук недоступен, секреты потеряны

Старый ноут украден или сломан — локальный `.env` недоступен.

- **Незакоммиченные локальные изменения потеряны.** Feature-ветки, не запушенные в `origin`, теряются вместе с локальным репо. Если фича дозрела до L2, имело смысл сделать `git push -u origin feature/<slug>` заранее — но если этого не произошло, прогресс придётся восстанавливать.

- **Если runtime app secrets потеряны и нет в парольном менеджере:**
  - Выпускай новые токены у провайдеров (новый OpenAI API key, новый Telegram-bot token и т.д.).
  - Вписывай в `.env` через редактор, не через чат.

**Полный порядок шагов Сценария B:**
1. Шаги 2–4 из Сценария A.
2. `mv .env.example .env`.
3. Получи новые app secrets у провайдеров.
4. Заполни `.env` через редактор IDE.
5. `./infra/start.sh` (финальная инициализация).

---

## Когда что-то пошло не так

- **`gh repo clone` падает с 404** → нет доступа к репо. Проверь права доступа в GitHub.
- **`./infra/start.sh` падает с prereq (gh / gitleaks / jq)** → pre-clone setup пропущен. Установи утилиту, скажи «готово», запусти start.sh снова.
- **`gh auth login` не проходит** → авторизуйся в браузере через device-code flow, который откроет `gh auth login`.
