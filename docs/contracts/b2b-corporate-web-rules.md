# Правила B2B-интерфейсов для корпоративных клиентов

## 1. Область применения и приоритет

Используй файл только для desktop B2B-интерфейсов корпоративных клиентов.

Сначала применяй базовые правила из client-web-rules.md, затем правила этого файла.

Базовые компоненты, типографику и состояния используй без изменений, если в задаче не показано подтвержденное B2B-отличие.

Не применяй правила файла к обычному клиентскому вебу и административным интерфейсам.

Если состав данных, логика или состояние не описаны в задаче, не определяй их самостоятельно.

## 2. Общие визуальные правила
- Для фоновых цветов используй только лавандовый #F0EBFF, бежевый #FFF0E6 и стандартные оттенки серого из client-web-rules.md.
- Не используй другие второстепенные цвета.
- Типографику полностью наследуй из client-web-rules.md.
- B2B-плашки собирай базовым уведомлением или инфоблоком.
- Нейтральную информацию не оформляй как ошибку.
- Используй официальные брендовые ассеты. Если ассет недоступен, используй нейтральный placeholder и не перерисовывай его.

## 3. Навигация в корпоративные сценарии
- Точки входа в корпоративные сценарии добавляй в базовые Header или Footer.
- Для раскрывающегося меню используй базовый Dropdown.
- Не создавай отдельную B2B-навигацию, если сценарий можно встроить в существующую структуру клиентского веба.
- Названия и состав пунктов бери из задачи.

## 4. Корпоративные данные
- Связанные данные организации объединяй в один логический блок.
- Для ввода реквизитов используй базовые поля и состояния из client-web-rules.md.
- Найденную или выбранную организацию показывай пользователю до подтверждения действия.
- Ошибку связывай с конкретным полем или этапом.
- Не определяй самостоятельно состав реквизитов, обязательность полей, правила проверки и редактирования.
- Не хардкодь ИНН, баланс, суммы, реквизиты и другие демонстрационные данные.

## 5. Бизнес-аккаунт
- Для разделов бизнес-аккаунта используй базовые Tabs.
- Активный раздел выделяй стандартным состоянием Tabs.
- Баланс и связанное с ним действие объединяй в одном смысловом блоке.
- Промоусловия показывай только при наличии соответствующих данных.
- Не придумывай роли, права доступа, лимиты, механику депозита и скидок.

## 6. B2B-отличия в товарных сценариях
- Ограничение для корпоративных клиентов показывай до основного действия с товаром.
- Используй отдельный заметный инфоблок, а не Tooltip.
- Одинаковую информацию не дублируй у каждого товара, если ее можно показать один раз на уровне корзины или заказа.
- Канал доставки, условия оплаты и ограничения бери из задачи или данных продукта.

## 7. B2B-отличия в оформлении заказа
- Используй базовый checkout из client-web-rules.md.
- Добавляй только B2B-поля и действия, необходимые конкретному сценарию.
- Корпоративную оплату связывай с выбранной организацией.
- Промокоды, бонусы, ЭДО и способы оплаты показывай только при наличии соответствующей логики в задаче.
- Не определяй самостоятельно обязательность полей, правила валидации, сохранения организации и документооборота.

## 8. Хорошо / плохо

**Хорошо:** использовать базовый компонент из client-web-rules.md и передать в него корпоративные данные.  
**Плохо:** менять внешний вид компонента только потому, что экран относится к B2B.

**Хорошо:** использовать только те B2B-блоки и состояния, которые нужны для задачи.  
**Плохо:** добавлять элементы из других корпоративных сценариев только потому, что они описаны в правилах.

**Хорошо:** если в задаче задано ограничение, показать его до действия, на которое оно влияет.  
**Плохо:** скрывать подтвержденное ограничение до момента, когда пользователь уже совершил действие.

**Хорошо:** использовать данные из задачи.  
**Плохо:** переносить суммы, реквизиты и тексты из демонстрационного макета.

## 9. Не определяй самостоятельно
- роли и права пользователей;
- состав и обязательность реквизитов;
- правила проверки ИНН;
- механику депозита и скидок;
- правила ЭДО;
- лимиты корпоративных товаров;
- доступные способы оплаты и доставки;
- тексты юридических условий.

## 10. Проверка результата

Перед завершением проверь:
- базовые компоненты взяты из client-web-rules.md;
- добавлены только необходимые B2B-отличия;
- не создан отдельный визуальный стиль для B2B;
- демонстрационные данные не захардкожены;
- продуктовая логика не придумана;
- ограничения показаны до соответствующего действия;
- официальные ассеты не перерисованы.
