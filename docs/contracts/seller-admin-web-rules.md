# Правила админских веб-интерфейсов для селлеров

## 1. Область применения и приоритет

Используй файл только для desktop-админских веб-интерфейсов селлеров Flowwow.

Не переноси правила админки на клиентские, B2B- и мобильные интерфейсы. Не используй компоненты, токены и сценарии других направлений без прямого подтверждения в материалах по админке. Исключение — палитра: родной палитры админки в этом файле нет, поэтому нейтральные и семантические цвета бери из client-web-rules.md §3.1.

Используй только подтвержденные компоненты, состояния, параметры и ограничения. Не собирай все описанное на одном экране: добавляй компонент, только если он нужен задаче или подтвержденному процессу.

Не придумывай не определенные файлом данные, роли, права, ограничения, порядок действий и продуктовую логику.

## 2. Применяй всегда

- Основной шрифт — Noto Sans. Выбирай готовый стиль по роли текста и применяй целиком: не подбирай и не меняй отдельно размер, line-height или weight.
- Собирай компонент по параметрам этого файла и переиспользуй его во всем прототипе; не создавай похожие варианты одного компонента.
- Дефолты для незаданных визуальных параметров: если размер, padding или цвет элемента в файле не задан, возьми значение, согласованное с заданными параметрами и токенами — radius 4 px, нейтральная шкала, семантические цвета по назначению, роли типографики из §3.1. Применяй его одинаково во всем прототипе и перечисли принятые дефолты оунеру. Стоп-правило §12 остается в силе для продуктовой логики: роли, права, валидацию, лимиты и переходы статусов не придумывай.
- Не считай демонстрационные названия, суммы, даты, статусы, тексты и значения правилами.
- Проверяй длинные значения, локализацию, empty, error, loading и disabled.
- Не смешивай состояния: загрузка, ошибка, отсутствие данных и отсутствие результатов поиска — разные состояния.
- Не заменяй компонент placeholder; он допустим только для визуального ассета или изображения.
- Используй официальные ассеты без перерисовки; не создавай логотипы, брендовые и платежные иконки.
- Mobile-макеты, адаптивность и мобильное поведение не добавляй.

## 3. Визуальная основа

### 3.1 Цвета и типографика

**Цвета**

Используй токены, а не визуально похожие HEX.

Нейтральную шкалу (Grey100–Grey600, Dark) и семантические цвета (Success, Warning, Error, Link) бери из client-web-rules.md §3.1. Не подбирай визуально похожие HEX и не вводи собственные оттенки границ.

Состояния neutral и info, которые требует Notification, оформляй на нейтральной шкале: фон Grey100, текст Dark. Отдельного Info-токена в доступной палитре нет, а Link предназначен для ссылок — различай neutral и info текстом и иконкой, а не цветом.

**Типографика**

Выбирай готовый стиль по роли текста; не заменяй роли по визуальному сходству и не подбирай размеры или начертания.

| Стиль | Когда использовать | Размер/line-height | Weight |
|---|---|---:|---:|
| `title-large` | самый крупный заголовок интерфейса | 40/48 | 700 |
| `title-page` | заголовок страницы | 32/40 | 700 |
| `title-modal` | заголовок модального окна или вложенной страницы с возвратом | 24/32 | 700 |
| `title-small` | заголовок раздела или подраздела | 20/28 | 700 |
| `subheading-bold` | подзаголовок с сильным акцентом | 16/24 | 700 |
| `subheading-semibold` | акцентный подзаголовок | 16/24 | 600 |
| `subheading-medium` | подзаголовок со средним акцентом | 16/24 | 500 |
| `subheading-regular` | обычный подзаголовок | 16/24 | 400 |
| `body-bold` | основной текст с сильным акцентом | 14/20 | 700 |
| `body-semibold` | акцентный основной текст | 14/20 | 600 |
| `body-medium` | основной текст со средним акцентом | 14/20 | 500 |
| `body-regular` | основной текст | 14/20 | 400 |
| `body-link` | ссылка внутри основного текста | 14/20 | 400 |

| `caption` | подпись или вспомогательный текст | 11/14 | 400 |

Не меняй weight ради выразительности. Цвет и состояния ссылок определяет Link.

Не используй Actay из брендового демонстрационного макета как интерфейсный шрифт.

### 3.2 Иконки и ассеты

Иконки — Material Symbols Outlined: Weight 300, Fill Off, Grade Normal, Optical size 24dp. Используй размеры 24, 20, 16 и 14 px; не масштабируй другой вариант.

Спецнаборы и avatar используй в подтвержденных размерах; фото заполняет контейнер через object-fit: cover.

## 4. Базовые компоненты

### 4.1 Кнопки и ссылки

Button: primary — главное действие, outline — альтернативное. Состояния: default, hover, active, disabled, loading. При loading перед текстом появляется loader: если иконки не было, ширина растет на loader и gap; высота не меняется.

Высоты: small 32, default 36, large 40, for inputs 48 px. Radius — 4 px; gap между иконкой и текстом — 8 px. Padding и размер иконки подбирай пропорционально высоте кнопки и держи одинаковыми во всем прототипе.

ButtonIcon используй для понятного действия без текста; danger — только для destructive actions. ButtonText — действие, Link — переход. Media button — только поверх media.

**Хорошо:** одно главное действие primary, альтернативное — outline.
**Плохо:** несколько равнозначных primary рядом без подтвержденного приоритета.

### 4.2 Controls, chips, tags и badges

Checkbox — множественный выбор, Radio — один вариант, Switch — бинарное состояние. Chips и tags используй для компактного выбора или отображения выбранного значения; drag, close и icon-only — только по сценарию. Badge показывает статус или характеристику, а BadgeBlur используется только поверх media.

Не придумывай семантику цвета, переходы между статусами, обязательность даты и доступность изменения статуса.

## 5. Формы и ввод данных

### 5.1 Input, TextArea и Select

Поле состоит из label, control и при необходимости helper/error text. Placeholder не заменяет постоянную подпись важного поля.

В зависимости от сценария поле может содержать дополнительные элементы:

- иконку до или после значения;
- единицу измерения;
- маску ввода;
- кнопку сброса заполненного значения;
- счетчик введенных символов и максимального количества;
- индикатор сохранения, загрузки или ошибки сохранения.

Добавляй элементы только по сценарию; не включай весь набор и не используй нефункциональные иконки.

Default input — 48 px, small — 36 px. Поддерживай default, hover, focus/open, filled, error, disabled и, если поле сохраняется автоматически, состояния loading, saved и save error. Ошибку показывай рядом с полем. TextArea — для многострочного текста, masked input — только при заданной маске. Single select — без checkbox, multiselect — с checkbox; поиск не сбрасывает selection.

**Хорошо:** ошибка связана с полем.
**Плохо:** ошибка поля заменена общим Notification.

### 5.2 Picker: дата, время и адрес

- DatePicker — одна дата; DateRangePicker — диапазон; DateTimeMaskedInput — время по заданной маске. Не объединяй их автоматически.
- Date input: H48, radius 4; single и range используй в подтвержденных размерах.
- Range panel содержит два календаря; размеры согласуй с параметрами одиночного календаря.
- Не придумывай формат, шаг, часовой пояс, disabled dates и ограничения диапазона.

AddressPicker — только для выбора или подтверждения адреса; autocomplete, карта и готовые точки — по сценарию.

- Input, выбранная точка и карта синхронизированы.
- Закрытие без сохранения не сохраняет изменение; Save disabled без валидного точного адреса.
- Error, no results и loading показывай отдельно.
- Не придумывай страны, источник геолокации, лимит точек, точность, права и API-поведение.

### 5.3 Upload

UploadFile — выбор/drag-and-drop; UploadFileList — строка выбранного файла. Поддерживай empty, hover, filled, loading/progress, finished и error.

Для изображений используй подтвержденные square/circle/product-photo варианты. View, replace, crop, delete, reorder и badge основного фото — только по сценарию.

Не восстанавливай форматы, максимальный размер, количество и правила валидации из примеров.

## 6. Поиск, фильтры и выбор

### 6.1 Фильтры

Поиск, фильтры и сортировка — разные controls. Один фильтр должен иметь единое состояние в строке, dropdown и modal.

Порядок в строке: search → частые фильтры → Все фильтры → Сбросить при наличии активных фильтров → вторичные действия.

Applied trigger показывает значение и локальный clear. Основная область открывает dropdown; clear сбрасывает только этот фильтр. При наличии Применить изменения остаются draft до подтверждения. Single/multi/binary/range собирай соответственно через radio/checkbox/switch/inputs+slider. No matches показывай внутри dropdown; ожидаемый недоступный фильтр — disabled с причиной.

Modal Все фильтры: header, навигация по группам, scrollable content и sticky footer с количеством результатов, глобальным сбросом и Применить.

Сброс работает на трех уровнях: один фильтр, текущая группа, все фильтры. Controls, tags и counters обновляются синхронно. Не придумывай зависимости и логику И/ИЛИ.

**Хорошо:** активный фильтр можно открыть для редактирования или сбросить крестиком.
**Плохо:** крестик открывает dropdown или глобально очищает все фильтры.

### 6.2 Sort и результаты

Sort держи вне modal фильтров. Показывай одно активное направление, если multi-sort не подтвержден. Не отображай сортировку как filter tag.

При apply оставляй строку фильтров видимой, блокируй повторный apply и показывай loader в results area. При no results сохраняй примененные фильтры и показывай Empty State; не очищай фильтры автоматически.

## 7. Таблицы, списки и массовые действия

### 7.1 Таблицы

Header может содержать checkbox/counter, labels, info, sort и actions. Выравнивание колонок в header и rows должно совпадать.

Rows могут содержать text, image, link, status, switch, input/select и icon actions. Используй существующие компоненты без отдельных табличных версий.

Для широкой таблицы используй horizontal scroll, а не чрезмерное сжатие данных.

Selection: none, partial и all через checkbox/indeterminate.

Table select all banner поддерживает последовательность: текущая страница → все страницы/все отфильтрованные → сброс. Закрытие баннера не снимает selection.

Не придумывай sticky columns, resize/reorder columns, inline-save, expandable rows, virtualization и permissions.

### 7.2 Pagination

Показать еще и постраничная навигация — разные сценарии.

- До 9 страниц показывай все; больше 9 — сокращай через многоточие.
- Back скрыт на первой странице, next — на последней.
- При одной странице номера и стрелки не показывай.
- Jump input используй только при количестве страниц больше 9.

Не придумывай page size, total, default page, сохранение позиции и серверную логику.

### 7.3 FloatingMenu

Показывай FloatingMenu только после фактического выбора объектов. Панель может содержать counter, cancel, действия и dark input/select/dropdown.

**Хорошо:** массовые действия появляются после выбора строк.
**Плохо:** панель постоянно видна без выбранных объектов.

## 8. Навигация и каркас страницы

### 8.1 Global Header, Page Header и Footer

Не смешивай глобальный HeaderNew и Page Header.

- HeaderNew содержит контекст магазина и глобальную навигацию; состав разделов, counters и CTA бери из задачи.
- Page Header содержит title, optional back/link/status и действия. Для основной страницы — title-page, для вложенной с возвратом — title-modal.
- Footer содержит только подтвержденные support/legal/language элементы; языки приходят с backend без переименования.

### 8.2 Side menu, Menu, Tabs и Steps

Side menu используется для навигации внутри раздела; ShopMenu — для выбора магазина, ActionMenu — для локальных действий, FloatingMenu — для массовых операций. Tabs — равноправные разделы, Steps — последовательный процесс.

Не придумывай глубину вложенности, порядок пунктов, click navigation по steps, skip/back и сохранение прогресса.

## 9. Обратная связь и состояния

Выбирай компонент по назначению:

- Tooltip v2 — короткое пояснение элемента.
- Tooltip — пояснение с заголовком или дополнительным текстом.
- Notification — временный результат действия поверх интерфейса.
- Important tip — важное постоянное сообщение в контексте страницы.
- Banner — второстепенное встроенное сообщение.
- Empty State — отсутствие данных, результатов или ошибка загрузки.

Tooltip не содержит критически важную информацию и не заменяет error, инструкцию или notification.

Notification поддерживает neutral/info/success/warning/error и размещается в правом верхнем углу.

Не придумывай timeout, queue, stacking и обязательность ручного закрытия.

**Хорошо:** ошибку загрузки показать как error state с повтором.
**Плохо:** показать отсутствие данных как успешный пустой экран без объяснения.

## 10. Modal

Базовый modal: overlay rgba(0,0,0,.6), white container, radius 10; title 24/32; close 24; content horizontal padding 32; footer padding 16x32.

Confirm/destructive modal объясняет последствия. Cancel — outline, destructive action — danger; checkbox подтверждения — только по сценарию.

SideNavModalWithSlot применяй для нескольких самостоятельных категорий; content scrolls independently от header/footer.

Не придумывай закрытие по overlay/Escape, focus trap, nested modal и выбор размера.

## 11. Админские сценарии и фичи

### 11.1 Статусы сохранения и объектов

Используй SavingStatus и ItemStatus только при подтвержденной логике. Цвет соответствует семантике состояния; text+icon и icon-only — разные варианты.

Не придумывай полный набор статусов, переходы, даты, автоматическое изменение и права.

### 11.2 Chats

ChatCard может содержать name, related ID, time, preview, avatar и unread indicator. Для даты используй один подтвержденный формат по давности сообщения.

Не придумывай сортировку, realtime, права, переход по карточке и логику unread.

## 12. Не определяй самостоятельно

- роли и права пользователей;
- состав экранов, таблиц, меню и навигации;
- обязательность полей и правила валидации;
- лимиты, форматы, маски и допустимые значения;
- переходы между статусами;
- доступность и порядок действий;
- зависимости фильтров;
- серверную логику, API и сохранение состояния;
- тексты ошибок, юридические тексты и демонстрационные данные;
- mobile- и adaptive-поведение.

## 13. Проверка результата

Перед завершением убедись, что:

- используется только desktop seller-admin scope;
- применены параметры компонентов из этого файла и палитра из client-web-rules.md §3.1, официальные ассеты не перерисованы;
- типографический стиль выбран по роли текста; его размер, line-height и weight не изменены самостоятельно;
- компонент выбран по задаче, а не добавлен только потому, что описан в файле;
- клиентские, B2B- и mobile-правила не перенесены;
- примерные данные не захардкожены;
- главное и второстепенные действия различимы;
- для кнопки в состоянии loading учтено появление loader: высота сохраняется, а ширина может увеличиться;
- предусмотрены нужные компоненту hover, focus/open, disabled, loading, error и empty; для автосохраняемых полей — saved и save error;
- ошибки связаны с конкретным полем или этапом;
- дополнительные элементы поля добавлены по сценарию; иконки функциональны, единицы, маски, clear и счетчики не избыточны;
- filters синхронизированы между строкой, dropdown и modal;
- destructive actions используют danger и подтверждение;
- роли, права, лимиты и продуктовая логика не придуманы;
- официальные ассеты не перерисованы.
