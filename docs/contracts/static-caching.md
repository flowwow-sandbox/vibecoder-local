# Кэширование статики

Заголовки кэша и сжатие здесь целиком на приложении. Локальный шаблон отдаёт статику своим
HTTP-слоем, и прокси, который дописал бы `Cache-Control` или сжал ответ за тебя, перед ним нет:
чего не поставил сам — не поставит никто.

## Что ставить

| Что отдаёшь | Заголовок |
|---|---|
| Файл с хэшем в имени (`index-BAwtAZkw.js`, `app.9f2c1d.css`) | `public, max-age=31536000, immutable` |
| Картинки и шрифты без хэша в имени | `public, max-age=604800` |
| То же, но видное только авторизованным | `private, no-cache` — копия хранится, но перед каждым показом сервер подтверждает право. `max-age` тут опасен: сотрудник, потерявший доступ, продолжит открывать файл из своего кэша до конца срока |
| Пользовательские загрузки (`/uploads/…`) | `private, no-cache`, **никогда** `public`. Если файл виден всем, кто вошёл, и права не меняются — допустим `private, max-age=604800` |
| HTML-документ | `no-cache` (проверять на сервере, но кэшировать) |
| Ответы API с данными | `no-store` |

`no-cache` и `no-store` — разное: первый разрешает хранить копию и переспрашивать, второй
запрещает хранить вовсе. Для HTML нужен первый, иначе каждый переход перекачивает документ.

Год (`max-age=31536000, immutable`) уместен ровно там, где имя файла версионирует само себя:
меняется содержимое — меняется имя, и старый ответ из кэша никому не достанется. На файл со
стабильным именем (`styles.css`, `report.pdf`) год ставить нельзя: правка такого файла до
конца срока не доедет до тех, кто его уже открывал.

## Сжатие — тоже на тебе

Текстовые ответы (HTML, `.js`, `.css`, `.svg`, JSON) отдавай сжатыми: включи gzip или brotli
в своём HTTP-слое. Бинарные форматы (`.png`, `.jpg`, `.webp`, `.woff2`) сжимать повторно
бессмысленно — они уже сжаты, и процессорное время уйдёт впустую.

## Условные запросы обязаны работать

Отдавать `Last-Modified` мало — сервер должен на него отвечать. Проверь так:

```bash
URL=http://localhost:$PORT/logo.png
H=$(curl -sI "$URL")
ETAG=$(printf '%s' "$H" | grep -i '^etag:' | cut -d' ' -f2- | tr -d '\r')
LM=$(printf '%s' "$H" | grep -i '^last-modified:' | cut -d' ' -f2- | tr -d '\r')

if [ -n "$ETAG" ]; then
  curl -sI -H "If-None-Match: $ETAG" "$URL" | head -1
elif [ -n "$LM" ]; then
  curl -sI -H "If-Modified-Since: $LM" "$URL" | head -1
else
  echo "нет ни ETag, ни Last-Modified — условные запросы невозможны в принципе"
fi
```

Валидатор выбирается по тому, какой заголовок сервер прислал: `ETag` проверяется через
`If-None-Match`, `Last-Modified` — через `If-Modified-Since`. Слать дату серверу, который отдаёт
только `ETag`, бессмысленно — он честно ответит `200`, и исправный кэш будет записан в сломанные.

Ответ обязан быть `304 Not Modified`. Если пришёл `200` при наличии валидатора — сервер игнорирует
условный запрос и гоняет файл целиком на каждом заходе. Это самая частая причина «портал тормозит»: страница
с полусотней картинок перекачивает их при каждом открытии.

## Чего не делать

- Не ставить `max-age=0` на файл с хэшем в имени — содержимое такого файла неизменно,
  а новая сборка получит новое имя.
- Не ставить `public` на что-либо, видимое только авторизованным: `public` разрешает хранить
  копию общим кэшам, а не только браузеру пользователя.
- Не отключать кэш «чтобы не путаться при разработке» — для этого есть режим разработки
  сборщика, а прод-заголовки должны быть прод-заголовками.
