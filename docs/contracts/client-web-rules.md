# Правила продуктовых веб-интерфейсов для клиентов
## 1. Область применения и приоритет
Используй файл для desktop-веба клиентского продукта Flowwow. Не применяй его к админским интерфейсам. Для B2B-интерфейсов корпоративного клиента файл служит базой: применяй его вместе с b2b-corporate-web-rules.md, который задает B2B-отличия поверх этих правил. Приоритет имеют явно описанные компонент, состояние и сценарий. Если в файле и проекте нет продуктовых данных, логики или сценария, не восполняй их предположениями: укажи, каких данных не хватает. Недостающие визуальные параметры разрешаются правилом дефолтов из §2.
## 2. Применяй всегда
- Основной шрифт: Roboto Flex
- Собирай компонент по параметрам этого файла и переиспользуй его во всем прототипе. Не создавай похожие варианты одного компонента
- Дефолты для незаданных визуальных параметров: часть значений в файле не задана — например цвета типов кнопок, padding отдельных размеров, геометрия полей и модальных окон. Возьми значение, согласованное с заданными параметрами и токенами: radius 12px, шкала Grey, семантические цвета по назначению, роли типографики из §3.2. Применяй его одинаково во всем прототипе и перечисли принятые дефолты оунеру. Останавливаться и запрашивать данные нужно для продуктовой логики: состава данных, прав, правил проверки и сценариев
- Не заменяй placeholder компонент, описанный в этом файле: собери его по заданным параметрам. Placeholder допустим только для визуального ассета, изображения или avatar, если это предусмотрено правилами
- Ширина компонента по умолчанию: hug content, если не задана фиксированная ширина или растяжение по контейнеру
- Не смешивай разные стили иконок, радиусы и типографические роли в одном сценарии
- Проверяй длинные названия, локализацию, empty, error, loading и disabled
- Используй официальный ассет; если его нет: нейтральный placeholder. Не перерисовывай логотипы, брендовые и платежные иконки
## 3. Визуальная основа
### 3.1 Цвета и эффекты
Основные токены:
- Dark #111111; White #FFFFFF
- Grey600 #888888; Grey400 #B8B8B8; Grey200 #E8E8E8; Grey100 #F6F6F6
- System/Purple #370A28; System/Logo #FF7864
- Success #5BAC72; Warning #FFB464; Error #CA341D; Link #649AFF
- Popup shadow: 0 4px 32px rgba(53,51,57,.08)
- Card hover: 0 6px 28px rgba(53,51,57,.12)
Не заменяй токены визуально похожими HEX. Семантические цвета используй по назначению.
### 3.2 Типографика
- display/medium: 45/56, 600; display/small: 36/44, 600
- headline/large-medium: 32/40, 600; headline/medium: 32/40, 500
- title/large: 22/28, 500; title-web/large: 22/28, 600
- title/medium: 16/22, 500; title-web/medium: 16/24, 600
- body/large: 16/24; body/medium: 14/20; body/small: 12/16
- label/large: 14/20, 500; label/medium: 12/16, 500; label/small: 11/16, 500
Не подбирай произвольный размер между ролями. Сначала выбери роль текста.
### 3.3 Иконки, логотипы и ассеты
- Используй официальный ассет и единое начертание: Outline либо Bold
- Не заменяй брендовые, социальные, store-, payment- и flag-иконки текстом или системным символом
- Логотип выбирай по контрасту к фону; не растягивай, не вращай, не перекрашивай и не добавляй эффекты
- Не собирай логотип из текста и произвольной иконки
## 4. Базовые компоненты
### 4.1 Кнопки и ссылки
#### Кнопки
Типы: Primary, Secondary, Tertiary; Accented: только в предусмотренных вариантах.
- XXSmall: 36px, radius 12px, padding 12px
- Small: 40px, radius 12px
- Medium: 50px, radius 12px
- Large: 60px, radius 12px
- Поддерживай Default, Hover, Pressed, Loader, Disabled и варианты с иконкой
- Icon-only используй для общеизвестного действия и добавляй tooltip, при неоднозначном значении
- Loader не должен менять ширину кнопки
#### Ссылки
- Текстовая ссылка использует Link #649AFF
- Стрелка располагается после текста; для многострочной ссылки выравнивается по нижней строке
- Не оформляй обычный текст как ссылку только цветом без интерактивного поведения
Хорошо: Primary для главного действия, Secondary для альтернативы. Плохо: две равнозначные Primary-кнопки рядом.
### 4.2 Controls и теги
- Checkbox: множественный выбор; Radio: один вариант; Switcher: немедленное включение/выключение настройки
- Не подменяй radio чекбоксами и наоборот
- Стрелочные кнопки: крупный контейнер 56×56, radius 12px, border 1px; компактный вариант: в предусмотренном компоненте
- Tag показывает статус или характеристику, но не заменяет кнопку. Цвет тега соответствует семантике
### 4.3 Поля ввода
- Поле с label используй в формах и для важных данных; placeholder не заменяет постоянную подпись
- Предусматривай Default, Focus, Filled, Error, Disabled и при необходимости: Success
- Ошибка располагается рядом с полем и объясняет, что исправить
- Text area используй для многострочного текста; не увеличивай однострочное поле для имитации textarea
- Иконки внутри поля не должны уменьшать читаемую область текста
Хорошо: «Телефон» + пример формата + конкретная ошибка. Плохо: подпись только в placeholder, исчезающая после ввода.
### 4.4 Pop ups и уведомления
- Modal содержит заголовок, контент, действия и явное закрытие
- Главное действие располагай первым по визуальному приоритету; опасное действие подтверждай отдельно
- Блокируй закрытие попапа только если без выбора действия нельзя продолжить сценарий. Например, если адрес недоступен для доставки, оставляй попап открытым до выбора: изменить адрес или посмотреть доступные товары. Иначе попап можно закрыть без выбора действия
- Toast сообщает о результате действия и исчезает автоматически; критичная ошибка должна оставаться доступной
- Cookie banner не перекрывает ключевые действия и содержит понятные варианты выбора
### 4.5 Pagination и Tabs
#### Pagination
- Показывай текущую страницу, переходы вперед/назад и доступный диапазон страниц
- Недоступные переходы переводятся в Disabled
- При большом числе страниц используй сокращение через многоточие, не выводи весь список
#### Tabs
- Tabs переключают равноправные представления в одном контексте
- Активный tab визуально выделен; disabled недоступен
- Не используй tabs как пошаговый мастер или замену основной навигации
- Названия короткие; длинный текст не должен ломать строку и индикатор
### 4.6 Cells, Avatar, Tooltip и Legend
- Cell: строка выбора или данных; сохраняй вертикальный ритм и кликабельность всей строки
- Search Cell показывает основной текст и при необходимости вторичную информацию
- Shop Cell может содержать avatar, название, рейтинг и метаданные; не перегружай второстепенными статусами
- Avatar использует готовое изображение или системный placeholder; не генерируй псевдофотографию
- Tooltip поясняет иконку или недоступное действие, но не хранит критически важную информацию
- Legend связывает маркер и значение; для одинаковой семантики используй одинаковый маркер
## 5. Поиск, фильтрация и выбор
### 5.1 Search dropdown
- Показывает найденные категории, товары или подсказки по логическим группам
- Клик по строке выбирает результат; отдельная стрелка раскрывает вложенный уровень, если предусмотрен
- Hover и выбранное состояние различимы
- Не смешивай навигацию и выбор в одной области без разделения
- При отсутствии результатов показывай понятное empty-состояние и следующий шаг
### 5.2 Фильтры
- Высота filter item: 40px, radius 12px, padding 8px 16px, gap 4px
- Порядок в ленте: сортировка > цена > фильтры категории > общие фильтры
- Сортировка показывает выбранный вариант, но не получает крестик сброса
- Активный одиночный фильтр показывает значение; множественный: число выбранных параметров
- Клик по основной области активного фильтра открывает редактирование; крестик сбрасывает только этот фильтр
- «Очистить фильтры (N)» показывай, когда есть активные фильтры; N: число примененных фильтров, не число значений одного фильтра
- Checkbox-фильтры переключаются сразу; диапазоны и множественный выбор подтверждаются действием «Показать», если предусмотрено сценарием
Хорошо: Популярные · Цена · Цветы в составе · Бесплатная доставка · Рейтинг. Плохо: сортировка после общих фильтров.
### 5.3 Категории
- Категории строятся по актуальным данным; не зашивай в интерфейс список-пример из макета
- Карточки категорий используют единое кадрирование, подписи и сетку
- Список категорий не прокручивается горизонтально. При уменьшении ширины сокращай число видимых иконок, а остальные категории показывай по нажатию на стрелку в раскрывающемся списке
- Многоуровневые категории сохраняют иерархию и возврат к родительскому уровню
### 5.4 Карта и адрес
- Карта используется для уточнения адреса доставки и зоны обслуживания
- Pin указывает точную выбранную точку; перемещение карты обновляет адрес по завершении движения
- Проверка возможности доставки выполняется автоматически при выборе точки
- После выбора адреса показывай только доставляющие по нему магазины. «Вне зоны доставки» используй, если доступных магазинов нет
- Не используй карту как единственный способ ввода: сохраняй поиск по тексту и найденный адрес
## 6. Карточки и контентные элементы
### 6.1 Карточка товара
- Карточка товара содержит изображение, название, цену и релевантные метаданные: рейтинг, условия доставки и др
- Бейджи «Последний» и «Уже собран» показывай для товаров с соответствующим статусом
- Изображение: главный визуальный элемент; не перекрывай товар декоративными плашками
- Цена и скидка читаются как единый блок; старая цена визуально вторична
- Длинное название ограничивай по строкам сохраняя высоту сетки
- Hover может добавлять тень и быстрые действия, без сдвига соседних карточек
- Контент 18+ скрывай или маркируй по продуктовому правилу; не показывай чувствительное изображение до разрешения
### 6.2 Карточка магазина
- Карточка магазина отличается от карточки товара и использует название, avatar/cover, рейтинг, категории и условия магазина
### 6.3 Контентные карточки
- Article card содержит cover, заголовок, роль/рубрику и метаданные при наличии
- Карточка целиком ведет в статью; вложенный CTA не должен конфликтовать с кликом по карточке
## 7. Каркас страницы
### 7.1 Header
- Используй актуальный трехуровневый header: UTP bar, основные действия, категории
- Используй нужные сценарию действия: логотип, каталог, поиск, адрес и время, профиль, корзину, язык/валюту
- Поиск занимает свободное пространство и не конкурирует с каталогом
- Адрес и время показывают текущий выбор и открывают его изменение
- Корзина отражает наличие товаров и итог; профиль не подменяй иконкой магазина
- При скролле допускается скрывать второстепенные уровни, сохраняя поиск, навигацию и действия пользователя
### 7.2 Footer
- Footer содержит нужные сценарию навигационные группы, города/категории, соцсети, store badges, язык/валюту и правовую информацию
- Списки городов и категорий формируются по актуальным данным, не фиксируются вручную в интерфейсе
- Не заменяй официальные store badges и социальные иконки текстом
- Правовые ссылки и реквизиты остаются доступными и читаемыми
### 7.3 Title group и промоблоки
- Title group связывает заголовок, пояснение и действие; действие визуально вторично
## 8. Продуктовые сценарии
### 8.1 Каталог и выдача
- Контентные подборки и истории отделяй от основной товарной выдачи
- Сетка карточек имеет единые колонки и интервалы; фильтры располагаются над результатами
- Пустая выдача объясняет причину и предлагает изменить запрос или фильтры
### 8.2 Страница магазина
- Header магазина содержит название, визуальный идентификатор, рейтинг и ключевые условия
- Категории магазина доступны рядом с ассортиментом и не дублируют глобальную навигацию
- Блок «О магазине» содержит полезную информацию; длинный текст сворачивается
- Отзывы, FAQ, адрес, УТП и инфоплашки добавляй при наличии данных
- Переведенный контент должен иметь понятный статус и возможность увидеть исходный текст, если предусмотрено продуктом
### 8.3 Корзина и оформление заказа
Для электронного товара не добавляй физическую доставку и связанные с ней статусы.
#### Корзина
- Показывай товары, количество, цену, доставку, скидки и итог
- Изменение количества и удаление пересчитывают итог без перезагрузки
- Условия бесплатной доставки формулируй однозначно: без условий или при достижении суммы заказа
- Не скрывай обязательные доплаты до финала
#### Оформление заказа
- Группируй данные по шагам: состав заказа > получатель > адрес и время > детали > оплата > итог
- Показывай заполненные данные и изменение каждого блока
- Промокод, бонусы, сертификат и чаевые не должны конкурировать с оплатой
- Ошибка привязана к конкретному полю или блоку; введенные данные сохраняются
Хорошо: итог включает товар, доставку, скидку и доплаты до оплаты. Плохо: обязательная сумма появляется после подтверждения.
### 8.4 Отзывы
- Показывай автора, оценку, дату, текст и ответ магазина при наличии
- Длинный текст сворачивай с явной кнопкой раскрытия
- Reviews slider используй как краткую подборку, не вместо полной страницы отзывов
### 8.5 Чат
- Различай входящие, исходящие и системные сообщения
- Показывай статус отправки/ошибки и повтор неуспешной отправки
- Composer содержит ввод, вложение и отправку; недоступные действия объяснены
- Фото и файлы показывают прогресс загрузки и ошибку
### 8.6 Блог
- Blog Header и заголовки используют отдельный стиль в рамках журнала
### 8.7 Главная страница
- Commercial cards, App promo, Delivery banner и подборки собирай из базовых компонентов этого файла
- У каждого блока одна цель и один главный CTA
- Промобаннер должен содержать и текст, и изображение: изображение поддерживает, но не заменяет сообщение
- Не смешивай несколько промомеханик в карточке
## 9. Проверка результата
Перед завершением убедись, что:
- применены токены и параметры компонентов из этого файла, официальные ассеты не перерисованы;
- placeholder не заменяет компонент;
- отсутствующие продуктовые данные и сценарии не восполнены предположениями, а принятые визуальные дефолты перечислены оунеру;
- для электронных товаров не добавлены физическая доставка и связанные с ней статусы;
- главный и второстепенные действия различимы;
- предусмотрены нужные hover, focus, pressed, disabled, loading, error и empty;
- длинные тексты и локализация не ломают сетку;
- примерные данные не зашиты в интерфейс;
- правила B2B и админских интерфейсов не применены к клиентскому вебу
