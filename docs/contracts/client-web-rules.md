# Правила продуктовых веб-интерфейсов для клиентов
## 1. Область применения и приоритет
Файл предназначен для desktop-веба клиентского продукта Flowwow. Для B2B применяй вместе с b2b-corporate-web-rules.md; для админских интерфейсов не применяй. Приоритет у явно описанных компонентов, состояний и сценариев. Если данных нет в файле и проекте, укажи, чего не хватает.
## 2. Применяй всегда
- Основной шрифт: Roboto Flex.
- Используй готовые компоненты и токены проекта. Не восстанавливай отсутствующий компонент по частичным параметрам и не придумывай цвета, размеры или отступы: укажи, каких данных не хватает.
- Placeholder допустим только вместо предусмотренного визуального ассета, изображения или avatar, но не вместо компонента. Он сохраняет место, размер, пропорции и положение исходного визуального элемента по референсу.
- По умолчанию ширина компонента — hug content, если не задана фиксированная ширина или растяжение по контейнеру.
- Не смешивай стили иконок, радиусы и типографические роли. Проверяй длинные названия, локализацию, empty, error, loading и disabled.
- Используй только ассеты, доступные отдельными файлами в проекте. Референс не является источником ассетов: не вырезай и не извлекай из него логотипы, иконки или изображения. Для отсутствующего контентного изображения или avatar используй нейтральный placeholder. Для иконок и логотипов применяй правила раздела 3.3.
- Референс задаёт структуру и геометрию экрана: состав, порядок, размеры и пропорции блоков, их выравнивание, расположение, отступы и радиусы. Сохраняй также относительное положение и размеры элементов внутри блоков. Не меняй композицию и не добавляй лишнее свободное пространство. Этот файл задаёт компоненты, токены и состояния. Не добавляй элементы, которых нет в задаче, референсе или правилах.

## 3. Визуальная основа
### 3.1 Цвета и эффекты
- Dark #111111; White #FFFFFF
- Grey600 #888888; Grey400 #B8B8B8; Grey200 #E8E8E8; Grey100 #F6F6F6
- System/Purple #370A28; System/Logo #FF7864
- Success #5BAC72; Warning #FFB464; Error #CA341D; Link #649AFF
- Popup shadow: 0 4px 32px rgba(53,51,57,.08)
- Card hover: 0 6px 28px rgba(53,51,57,.12)
Не заменяй токены похожими HEX; семантические цвета используй по назначению.
### 3.2 Типографика
- display/medium: 45/56, 600; display/small: 36/44, 600
- headline/large-medium: 32/40, 600; headline/medium: 32/40, 500
- title/large: 22/28, 500; title-web/large: 22/28, 600
- title/medium: 16/22, 500; title-web/medium: 16/24, 600
- body/large: 16/24; body/medium: 14/20; body/small: 12/16
- label/large: 14/20, 500; label/medium: 12/16, 500; label/small: 11/16, 500
Не подбирай произвольный размер между ролями. Сначала выбери роль текста.
### 3.3 Иконки и логотипы
- Для интерфейсных иконок временно используй Material Symbols Outlined: https://fonts.google.com/icons, Fill 0, Weight 300, Grade 0, Optical size 24. Не перерисовывай иконки вручную.
- Логотип используй только из доступных официальных ассетов. Если ассета нет, сохрани место по референсу и выведи placeholder «Логотип».
## 4. Базовые компоненты
### 4.1 Кнопки и ссылки
#### Кнопки
Типы: Primary, Secondary, Tertiary; Accented — только в предусмотренных вариантах. Radius 12px.

Состояния:
- Primary: default/pressed System/Purple + White; hover #7E4D6C + White; disabled Grey100 + Grey400.
- Secondary: default/pressed White + Dark + border 1px Dark; hover Grey100 + Dark + border Dark; disabled Grey100 + Grey400 без border.
- Tertiary: default/pressed Grey100 + Dark; hover Grey200 + Dark; disabled Grey100 + Grey400.
- Accented: default/pressed System/Logo + White; hover System/Logo 80%.

Размеры:
- Text: XXS H36 P12; S H40 P14×43; M H50 P14×43; L H60 P14×43.
- Text+icon: XXS H36 P12 G4 I24; S H40 P8×44 G4 I24; M H50 P13×44 G8 I24; L H60 P14×44 G12 I32.
- Icon-only: XXS 36 P6 I24; S 40 P8 I24; M 50 P13 I24; L 60 P14 I32.

Icon-only — только для общеизвестного действия; для неоднозначного добавляй Tooltip.
Loader заменяет текст и центрируется: 48×18, точки 12×12, gap 6; размер кнопки не меняется. Primary/Accented — светлый, Secondary/Tertiary — тёмный.
Поддерживай Default, Hover, Pressed, Loader, Disabled и только предусмотренные сочетания типа/состояния/размера.

#### Ссылки
- Текстовая ссылка использует Link #649AFF
- Стрелка располагается после текста; для многострочной ссылки выравнивается по нижней строке
- Не оформляй обычный текст как ссылку только цветом без интерактивного поведения
### 4.2 Controls и теги
- Checkbox — множественный выбор, Radio — один вариант, Switcher — немедленное переключение настройки; не подменяй их друг другом.
- Стрелочные кнопки: крупный контейнер 56×56, radius 12px, border 1px; компактный вариант используй только если он задан в задаче, референсе или доступен в проекте.
- Tag показывает статус или характеристику, но не заменяет кнопку; цвет соответствует семантике.
### 4.3 Поля ввода
#### Input
Все варианты Input: radius 12px, border 1px.

`With label` — основной вариант со встроенной подписью. В пустом поле подпись отображается как основной текст; в Focus и после ввода уменьшается и перемещается над значением.

- Размеры: H50, horizontal padding 16px.
- Типографика: подпись в пустом поле и значение — body/large 16/24; поднятая подпись — body/small 12/16.
- Состояния: Default — фон White, border Grey200, подпись Grey600; Hover — фон Grey100; Focus/Filled — border Dark, значение Dark; Error — border и подпись Error, значение Dark; Empty error — border и подпись Error; Disabled — border Grey200, подпись и значение Grey400.
- Адресный вариант: H60, leading icon 24×24px, trailing icon 16×16px, gap 12px.
- Маску, код страны, leading/trailing icon и clear добавляй только в предусмотренных вариантах компонента.

`Without label` — вариант без встроенной подписи. Используется в поиске.

- Базовый вариант: H60, horizontal padding 16px, trailing icon 16×16px.
- Состояния: Default — border Grey200; Hover — фон Grey100; Focus/Focus filled/Filled — border Dark; Error — border Error; Disabled — border и текст Grey200.
- Search: H40, padding 7px 16px, gap 12px, leading icon 20×20px, trailing icon 16×16px.
Для формы редактирования с явным сохранением действие сохранения недоступно до изменения данных и снова становится недоступным после успешного сохранения.

#### Text area
Используется для большого текста, например комментария курьеру. Высота фиксированная.

- H120, radius 12px, border 1px, horizontal padding 16px.
- Default — border Grey200, подпись body/large 16/24.
- Hover — фон Grey100, padding 8px 16px.
- Focus — border Dark, padding 5px 16px, gap 2px; подпись body/small 12/16.
- Filled/Scroll — border Dark, padding 5px 16px 0, gap 2px.
- Error — border, подпись и превышенный счётчик Error; значение остаётся Dark.
- Для поля с лимитом показывай счётчик снизу справа: обычный — Grey600, превышенный — Error. При переполнении используй внутренний scroll; scrollbar 4px.

`Dropdown input` не используй: оба его варианта отмечены в дизайн-системе как пока неиспользуемые.
### 4.4 Pop ups и уведомления
#### Modal
- Базовый desktop-размер: W538px; крупный вариант — W806px.
- Контейнер: White, radius 20px, padding 35px, эффект Popup shadow.
- Заголовок: title-web/large 22/28; основной текст — body/large 16/24.
- Gap между заголовком и описанием — 8px; между контентом и действиями — 20px.
- Close: 24×24px, справа от заголовка.
- Actions: одна кнопка — на всю ширину; две — в строку, gap 16px, H50. Если текст не помещается — вертикально, gap 8px, общая H108.
- Для W806px используй структуру, заданную в задаче, референсе или доступном компоненте проекта.
- Не создавай новые размеры и компоновки, если они не заданы в файле, задаче, референсе или проекте.
- Главное действие — первое по приоритету; опасное подтверждай отдельно. Блокируй закрытие только если без выбора нельзя продолжить.

#### Toast и системные уведомления
- Toast сообщает о результате и исчезает автоматически; критичная ошибка остаётся доступной. Cookie banner не перекрывает ключевые действия и содержит понятный выбор.
### 4.5 Pagination, Tabs и вспомогательные элементы
- Pagination показывает текущую страницу, переходы и доступный диапазон; недоступные переходы — Disabled, большой диапазон сокращай многоточием.
- Tabs переключают равноправные представления в одном контексте: активный tab выделен, disabled недоступен. Не используй tabs как мастер или основную навигацию; длинные названия не должны ломать строку и индикатор.
- Cell — кликабельная строка выбора или данных. Search Cell содержит основной и при необходимости вторичный текст; Shop Cell — avatar, название, рейтинг и метаданные без лишних статусов.
- Avatar использует готовое изображение или системный placeholder; не генерируй псевдофотографию.
- Tooltip поясняет иконку или недоступное действие, но не хранит критичную информацию. Legend связывает маркер и значение; одинаковая семантика использует одинаковый маркер.
## 5. Поиск, фильтрация и выбор
### 5.1 Search dropdown
- Группируй найденные категории, товары и подсказки. Клик по строке выбирает результат; отдельная стрелка раскрывает вложенный уровень, если он предусмотрен.
- Hover и выбранное состояние различимы. Не смешивай навигацию и выбор без визуального разделения; при отсутствии результатов показывай empty-состояние и следующий шаг.
### 5.2 Фильтры
- Filter item: H40, radius 12px, padding 8px 16px, gap 4px. Порядок: сортировка > цена > фильтры категории > общие фильтры.
- Сортировка показывает выбранный вариант без крестика. Одиночный фильтр показывает значение, множественный — число выбранных параметров.
- Клик по активному фильтру открывает редактирование; крестик сбрасывает только его. «Очистить фильтры (N)» показывай при активных фильтрах, где N — число фильтров, а не выбранных значений.
- Checkbox-фильтры переключаются сразу; диапазоны и множественный выбор подтверждаются кнопкой «Показать», если это предусмотрено сценарием.
### 5.3 Категории, карта и адрес
- Категории строятся по актуальным данным; не зашивай список из примера. Сохраняй единое кадрирование, подписи, сетку, иерархию и возврат к родительскому уровню.
- Не используй горизонтальный scroll категорий: при уменьшении ширины сокращай число видимых иконок, остальные раскрывай по стрелке.
- Карта уточняет адрес и зону обслуживания. Pin показывает выбранную точку; после движения карты обновляй адрес и автоматически проверяй доставку.
- После выбора адреса показывай только доставляющие магазины; при их отсутствии — «Вне зоны доставки». Сохраняй текстовый поиск и найденный адрес как альтернативу карте.
## 6. Карточки и контентные элементы
- Карточка товара содержит изображение, название, цену и релевантные метаданные: рейтинг, условия доставки и др. Бейджи «Последний» и «Уже собран» показывай только для соответствующего статуса.
- Изображение — главный визуальный элемент: не перекрывай товар декоративными плашками. Цена и скидка читаются как единый блок, старая цена визуально вторична.
- Длинное название ограничивай по строкам, сохраняя высоту сетки. Hover может добавлять тень и быстрые действия без сдвига соседних карточек.
- Контент 18+ скрывай или маркируй по продуктовому правилу; не показывай чувствительное изображение до разрешения.
- Карточка магазина отличается от карточки товара и использует название, avatar/cover, рейтинг, категории и условия магазина.
- Article card содержит cover, заголовок, роль/рубрику и метаданные при наличии; карточка целиком ведёт в статью, вложенный CTA не должен конфликтовать с кликом.
## 7. Каркас страницы
- Сетку основного контента используй из референса.
### 7.1 Header
- В верхней части desktop-интерфейса оставляй область 50 px под рекламный banner и помечай её текстом «Место под рекламный баннер». Сам banner не воспроизводи.
- Ниже располагай продуктовое меню высотой 123 px и воспроизводи его по референсу.
- Суммарная высота верхней области до основного контента — 173 px.
### 7.2 Footer и Title group
- Footer содержит нужные сценарию навигационные группы, города/категории, соцсети, store badges, язык/валюту и правовую информацию. Списки городов и категорий формируй по актуальным данным.
- Не заменяй официальные store badges и социальные иконки текстом; правовые ссылки и реквизиты оставляй доступными и читаемыми.
- Title group связывает заголовок, пояснение и действие; действие визуально вторично.
## 8. Продуктовые сценарии
### 8.1 Каталог и магазин
- Контентные подборки и истории отделяй от основной выдачи. Сетка карточек использует единые колонки и интервалы, фильтры располагаются над результатами.
- Пустая выдача объясняет причину и предлагает изменить запрос или фильтры.
- Header магазина содержит название, визуальный идентификатор, рейтинг и ключевые условия; категории магазина располагаются рядом с ассортиментом и не дублируют глобальную навигацию.
- Блок «О магазине» может содержать адрес, УТП, FAQ, отзывы и инфоплашки; длинный текст сворачивай. Для переведённого контента показывай статус и исходный текст, если это предусмотрено продуктом.
### 8.2 Корзина и оформление заказа
- Для электронного товара не добавляй физическую доставку и связанные статусы.
- Корзина показывает предусмотренные задачей или референсом товары, действия и итог; изменение количества и удаление пересчитывают итог без перезагрузки.
- В оформлении группируй данные по сценарию; показывай заполненные данные и возможность изменить предусмотренные блоки.
- Ошибку связывай с конкретным полем или блоком и сохраняй введённые данные.
### 8.3 Отзывы, чат, блог и главная
- В отзывах показывай автора, оценку, дату, текст и ответ магазина; длинный текст сворачивай с явным раскрытием. Reviews slider используй только как краткую подборку.
- В чате различай входящие, исходящие и системные сообщения; показывай статус отправки/ошибки и повтор. Composer содержит ввод, вложение и отправку; для фото и файлов показывай прогресс и ошибку.
- Blog Header и заголовки используют отдельный стиль журнала.
- Для Commercial cards, App promo, Delivery banner и подборок сохраняй композицию из референса или доступного компонента проекта. У каждого блока одна цель и один главный CTA; изображение поддерживает, но не заменяет текст.
## 9. Проверка результата
Перед завершением сравни результат с референсом по общей композиции: ширине и высоте блоков, их пропорциям, выравниванию, отступам, радиусам и положению элементов внутри них. Проверь, что одинаковые по роли элементы сохраняют согласованные размеры, пропорции и уровни выравнивания, а из-за отсутствующих ассетов не изменилась геометрия экрана. В финальном ответе обязательно выведи список «Не хватает для финальной версии» со всеми недостающими ассетами и компонентами. В финальном списке перечисли все системные иконки по назначению.
